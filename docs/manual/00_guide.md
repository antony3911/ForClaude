# 導讀：如何使用本手冊

> 這份手冊寫給**完全沒有 FPGA 經驗**、但要以 LightNobel（ISCA 2025）為起點做研究或專題的人。
> 讀完後你應該能：說明問題的來源、解釋每個優化手法為什麼有效、看懂程式碼與 HLS 報告、自己下指令跑實驗，並用同樣的方法讀下一篇 paper。

### 先備知識
- **需要：** 基本的程式概念（變數、迴圈、陣列）、高中程度的數學（次方、平方根、比例）。
- **不需要：** FPGA、硬體設計、生物學、深度學習的背景；手冊會從頭解釋。
- 看得懂一點 C/C++ 會比較輕鬆，但不是必要的（程式碼都有逐段說明）。

## 閱讀慣例

### 每個概念的說明順序
1. **白話直覺**：用比喻（例如「倉庫 vs 料理台」）先建立印象。
2. **正式定義**：公式或精確的說法。
3. **本專題的例子**：附上實際數字。

### 每章的固定結構
- 開頭的「**本章重點**」：先知道這章要講什麼。
- 結尾的「**本章小結**」：複習。
- 最後的「**自我檢測**」：答案在附錄 C。

### 指令的狀態圖示（附錄 A）
| 圖示 | 意思 |
|---|---|
| ✅ | 已經做過 |
| 🔜 | 下一步會用到 |
| 🟡 | 進行中 |
| ⬜ | 之後可以做 |
| ⚠️ | 小心使用（可能刪除資料） |

### 其他
- 程式碼區塊中的 `#` 後面是說明文字，不需要輸入。
- 「L」一律代表**蛋白質的長度**（胺基酸個數），「C」代表 **channel 數**（本專題為 128）。
- 數字若標示「估計」、「假設」，代表還沒有經過實際量測驗證。
- 手冊中的狀態（例如「進行中」）以 **2026-09-26** 為準；最新進度請看 `docs/PROJECT_LOG.md`。

## 最短上手路徑（10 分鐘）

如果你手上有 server 帳號，照著做就能跑出第一個結果：
```bash
git clone -b claude/lightnobel-memory-optimization-yhokyc https://github.com/antony3911/ForClaude.git
cd ForClaude/fpga/trimul
make csim                      # 幾秒：確認 5 個版本都算對（看到 ALL PASS）
make hls KERNEL=trimul_v2      # 幾分鐘：產生 v2 的硬體報告
head -n 60 hls_prj/trimul_v2/sol/syn/report/trimul_v2_csynth.rpt
```
每一行在做什麼，見附錄 A；報告怎麼看，見 8.11 節。
